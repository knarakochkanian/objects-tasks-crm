# Решения, допущения и ограничения

## Организация работы

- CRM предназначена для одной компании. Разделения данных по нескольким организациям нет.
- У пользователя одна роль: постановщик или исполнитель. Постановщиков может быть несколько; каждый может управлять задачами любого автора.
- Учётные записи и роли создаёт администратор. Самостоятельная регистрация, экран управления сотрудниками и пользовательское восстановление пароля не реализованы.
- Название и адрес объекта обязательны. Для задачи обязательны название, объект и исполнитель; описание может быть пустым. Ограничения длины и непустые значения проверяются в интерфейсе и базе.

## Задачи и история

- Назначить задачу можно только исполнителю. Постановщик может изменить исполнителя или объект без смены статуса.
- После переназначения прежний исполнитель теряет доступ при последующих запросах к базе; новый исполнитель видит всю историю задачи. Уже загруженная пользователем информация не может быть отозвана.
- Исполнитель видит в общем объекте только назначенные ему задачи.
- Принятую задачу можно редактировать и удалить, но нельзя повторно открыть через смену статуса. Для нового цикла работы создаётся новая задача.
- История фиксирует создание и каждую смену статуса. Изменение названия, описания, объекта или назначения не создаёт запись смены статуса. Автор задачи и дата создания неизменны.
- Имена и роли сотрудников доступны вошедшим участникам компании для отображения автора, исполнителя и участников истории. Email и данные Auth через этот справочник не выдаются.
- Удаление логическое: записи скрываются из рабочих списков и остаются в базе. Удаление объекта скрывает все его задачи после подтверждения. История не удаляется через API; восстановления в интерфейсе нет.

## Технические решения

- React-приложение обращается к Supabase напрямую. Правила доступа, допустимые переходы и журналирование находятся в PostgreSQL, поэтому действуют независимо от интерфейса.
- Все изменения проходят через ограниченный набор RPC. Прямой записи в таблицы у пользователей приложения нет.
- Сохранение, удаление и смена статуса требуют актуального номера версии. Конкурентный запрос отклоняется вместо перезаписи чужих изменений.
- Данные повторно загружаются после действий, при возврате на вкладку и обновлении страницы. Постоянная доставка изменений через Realtime не подключена; защита базы и проверка версии действуют независимо от этого.
- Локальные скрипты запуска и наполнения работают только с локальным Supabase. Случайные пароли демонстрационных аккаунтов хранятся в исключённом из Git файле `.local/test-accounts.json`; административный ключ не записывается во фронтенд.
- Настройки отключения регистрации из локального `config.toml` не переносятся в облачный проект автоматически. В облачной демонстрации регистрация и анонимный вход отключены отдельно, вход по email и паролю включён. При повторном развёртывании эти настройки нужно задать и проверить заново.
- Демонстрация размещена на Vercel с отдельным Supabase на бесплатном тарифе в регионе `eu-central-1`. Все миграции применены, подготовлены три объекта, семь задач и четыре пользователя. Облачные учётные данные независимы от локальных и передаются отдельно.

## Текущие ограничения

[Демонстрационная версия](https://objects-tasks-crm-lilac.vercel.app) предназначена для знакомства с рабочим процессом на учебных данных. Репозиторий включает приложение, миграции, локальное окружение, проверки и инструкцию повторного развёртывания. Проверки конкретного облачного окружения выполняются отдельно от локальных тестов и CI.

Приоритеты, сроки, вложения, чаты, уведомления и отдельные доски не реализованы. Также не проверены производительность на большом объёме данных, резервное копирование, мониторинг и восстановление после аварий. Перед использованием с рабочими данными компании эти эксплуатационные требования нужно определить и настроить.

Локальные тесты охватывают бизнес-правила, ограничения базы, реальные запросы к Supabase и действия в браузере. Состав проверок и зафиксированные результаты приведены в [README](../README.md#проверки). Результаты удалённого CI доступны отдельно во вкладке Actions репозитория.
